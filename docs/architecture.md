# 程序结构

## 运行方式

浏览器只负责输入和显示。FastAPI 管理比赛会话，推进 HighwayEnv，并调用本地模型。前端不会计算碰撞、奖励或比赛成绩。

`Start-Game.cmd` 调用 `server.launch`，核对前端构建和服务版本。默认监听 `127.0.0.1:8765`；如果已有不匹配的服务，会换一个可用端口。服务与前端构建按文件内容校验，因此 Git 检出产生的修改时间变化不影响启动。

## 一次对决

1. `POST /api/game/sessions` 创建玩家与 PPO 的独立环境，两侧使用相同初始种子。
2. 前端每 200 ms 发送一次 `POST /api/game/sessions/{id}/step`，包含玩家动作；服务端同时推进双方。
3. 返回两侧快照、风险提示、进度与模型决策信息。完成比赛后，服务端只保存一次结果。
4. `DELETE /api/game/sessions/{id}` 释放会话；退出页面和开始新局都会清理旧会话。

同一回合不并发发送步进请求。新回合有独立 ID，旧请求迟到不会覆盖新状态。暂停停止发送后续请求，已经执行中的一步可以完成。

## 前端

- `GameApp.tsx`：主菜单、赛程、结算和回放状态。
- `useDriving.ts`：创建会话、倒计时、步进、暂停和关闭。
- `useDriveControls.ts`：键盘与按钮。左右换道点按，上下调速允许持续输入；每个方向轴最多保留一个待执行动作。
- `RoadScene.tsx`：单个 WebGLRenderer，分别绘制玩家和对手视口。画面未就绪或图形上下文丢失时暂停比赛，可重建渲染器后继续。
- `scene/DrivingView.ts`、`scene/scenery.ts`、`scene/assets.ts`：快照插值、场景、车辆素材和资源释放。
- `ModelShowcase.tsx`：展示服务端返回的冻结训练报告。
- `sound.ts`：引擎、事件音效和音乐，首次用户操作后启用音频。

物理频率为 15 Hz，决策频率为 5 Hz。画面在快照之间插值，不外推车辆位置，也不影响仿真。切换窗口暂停驾驶和回放；恢复焦点后由用户继续。

## 模型和评估

`server/catalog.py` 读取部署清单，并校验权重和报告哈希。正式对手为 `v3_expert`；其他算法保留作实验对照。模型使用结构化状态，游戏画面不参与推理。

训练参数、奖励和测试口径见[训练与评估](training.md)。修改环境或奖励后需要重新训练、选择和评估，不能沿用旧报告中的成绩。

## 存档

`server/records.py` 保存 SQLite 比赛记录和回放快照，默认目录为 `artifacts/game/`。用 `LANE_SHIFT_DATA_DIR` 可以指定其他目录。浏览器与音频测试使用各自的临时目录，不写入日常驾驶记录。

回放读取已保存的快照，不重新运行模型。回放定位以双方较晚的仿真时间为准，玩家先发生碰撞后仍能查看对手剩余的行程。

## 目录约定

- `rl_course/`：环境、训练、评估与模型发布。
- `server/`：本地服务、会话、存档和启动检查。
- `web/`：游戏界面和浏览器测试；`dist/` 随仓库提交，供无 Node.js 的电脑启动。
- `artifacts/experiments_v2/`、`artifacts/experiments_v3/`：训练和评估归档，不覆盖已有冻结结果。
- `docs/defense/`：幻灯片、讲稿和生成源文件。

旧实验网页已移除，原 `/research` 地址跳转到游戏首页。历史环境和训练记录保留，供模型来源核对及复现。
